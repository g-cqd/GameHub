# eaanticheat.sys acquisition from EA CDN — investigation result

Date: 2026-10-14, 14:15-14:35 CEST. Task: bring in `eaanticheat.sys` from EA's CDN
(Pathway C of the 14:15 investigation report). All steps performed and verified this session.
Evidence directory: /Users/gc/eaac-archive/eaanticheat-cdn-20261014/

## RESULT: Pathway C is a dead end. EA does not statically host the driver.
The driver cannot be downloaded from the CDN by URL; it is no longer bundled in the
installer; it is only materialized inside a platform-valid runtime on real Windows.
The only practical acquisition route is Pathway A: copy the genuine, signed
`C:\Windows\System32\drivers\eaanticheat.sys` from a real Windows 10/11 machine with an
EAAC title installed. The alternative is deep reverse engineering of the packed
GameService/Installer runtime download flow (multi-day effort, out of scope).

## What was done and measured

4. CDN probing: unknown paths 301-redirect to error.html; the only real object at the CDN

## Interpretation

The driver acquisition on real Windows happens inside a platform-valid runtime context
(gameservice/installer self-test), gated on checks Wine cannot satisfy. This is consistent
with real-Windows forum reports ("installer reports Install success but eaanticheat.sys is
missing") when those platform checks fail. Forcing those checks to pass under Wine would be
identity-masking work, which is out of scope per the project's no-evasion directive.
