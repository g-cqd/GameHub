# 2026-10-31 (06): Wolfenstein II fullscreen, roadmap work while the owner played

**Wolfenstein II (roadmap 0029):** five more Wine fixes, each found in a trace and checked again with the owner.
- Present scaling was never requested, because of an ordering bug in `convert_instance_create_info` and a KHR/EXT
  mismatch (9001874).
- A decorated window whose client area fills the screen is now treated as fullscreen.
- In the Space: the Dock and menu bar stay hidden (probed natively first), the hidden cursor is confined, and
  minimizing keeps the window in its Space.
- `ShowWindow` no longer doubles the window size for DPI-unaware programs (cb9d708).

The prefix's `FullscreenMode` went from `borderless` to `native` with the owner's agreement. Open: the mouse after
Cmd-Tab.

Two wrong assumptions on the way:
- "the menu bar reveal comes from the cursor clip": the game never clips in gameplay;
- "the delegate's options are enough": AppKit replaces them after a restore.

The `NSLog` diagnostics that showed this were removed before the commit.

**Roadmap work while the owner played** (no prefix restarts):
- 0005: the overlay files are moved before every Steam game. On the next launch it moved seven files that Steam
  had restored, so the overlay had been in the earlier Wolfenstein sessions.
- 0021: `hub stop` asks Steam to quit first and refuses while a game runs.
- 0016: `hub play` hands macOS activation to the game. It only runs without `--no-wait`; untested.
- 0020: scratch files and the ExT2 scripts removed (archived).
- 0011: winecoreaudio's `-10851`. A native probe showed AUHAL rejects a channel bitmap whose bit count differs from
  the stream's channel count, including mask 0, and accepts matching masks. The first guess (bitmap tags in
  general) was wrong and reverted. Fixed in a23f119.

**Hub:** `--debug` now restarts a running launcher.

**Not verified:** activation through the hub, the audio fix in a game, the overlay with a client update during play.
