## 4. Launcher ↔ Session Protocol

### How Launcher Starts Session (NFS2015SessionClient.swift)

**Executable Lookup:**
- Bundle.main.bundleURL is used to find session executable (NFS2015SessionClient.swift:117, process.executableURL = paths.session).
- AppPaths resolves paths.session from bundle (set in LauncherCore).

**Process Arguments:**
- Format: `[bundle.path, "--support", supportFolder.path, actionFlag, [--request, filePath]]`
- Example (line 94-115):
  ```
  arguments = [paths.bundle.path, "--support", support.path, "--play"]
  case .configure(let settings):
    draft = try writeRequest(settings)
    arguments += ["--request", draft.path]
  ```
- Executable: `paths.wine` (AppPaths provides it from bundle/Resources).
- Environment: `["PATH": "/usr/bin:/bin:/usr/sbin:/sbin"]` (line 120).
- Current directory: bundle's parent folder (line 119).
- stdio: All to session log file (lines 121-123).

### CLI Verbs/Flags Parsed by Session (SessionOptions.swift, lines 10-14)
- `--prepare` - Prepare bundled game on first launch.
- `--play` - Start game with running EA app.
- `--configure` - Apply game settings changes.
- `--choose-installation` - Adopt player's Windows folder.
- `--enable-controller` - Record controller in registry.
- `--install-client` - Run EA app installer.
- `--open-client` - Start EA app for sign-in.
- `--configure-metalfx` - Save/reset MetalFX choice.
- `--configure-diagnostics` - Save/reset diagnostics preference.
- `--configure-sidecar` - Save/reset x87 sidecar preference.
- `--configure-experiments` - Save/reset Wine experiments preference.

### Exit Codes (SessionMain.swift, NFS2015SessionClient.swift)
- **0:** Success.
- **73:** alreadyRunning (game session already in progress, from line 14 and 137).
- **1:** General error.

## 6. Profiles / Saves / Backups Features

### Backups (NFS2015OptionsBackups.swift)
- **Original:** Copy of game file before this app first modified it. Preserved indefinitely.
- **Previous:** Copy of game file before last save by this app. Updated on each save.
- **Location:** Backups/ subfolder in ~/Library/Application Support/NFS2015Mac/.
- **Files:** original (no extension), previous (no extension).
- **Recovery:**
  - "Restore Game Defaults…" reads original, writes it back, button disabled if no original exists (NFS2015Model.swift:237).
  - "Undo Last Save" reads previous, writes it back, button disabled if no previous exists (line 238).

### No Profiles Feature
- Settings are global (no named profiles).
- Only one set of settings per installation.
- Player can save, restore original, or undo last save.

- **Preference struct:** NFS2015SidecarPreference (enabled: Bool).

### Wine Experiments (Rosetta workaround and three experiments)
- **Preference struct:** NFS2015WineExperimentsPreference (flushToggle, protectToggle, tracePage, rwxWxEmulation: all Bool).
- **Environment:** WineExperimentSwitches (environment dict) with keys WINE_RWX_EMULATE, WINE_PATCH_*:
  - `rwxWxEmulation` → `WINE_RWX_EMULATE=1` (Rosetta workaround, on by default).
  - `flushToggle` → `WINE_CPU_TOPOLOGY_FLUSH_TOGGLE=1` (experiment, off by default).
  - `protectToggle` → `WINE_CPU_TOPOLOGY_PROTECT_TOGGLE=1` (experiment, off by default).
  - `tracePage` → `WINE_TRACE_PAGE=0x1B30000` (experiment, off by default; records memory calls).
- **Storage:** wine-experiments-preference.json (4096 byte limit).
- **UI:** Toggles with explanatory text, Save/Reset buttons (NFS2015ExperimentsView.swift).
- **Rosetta Workaround:** Addresses NFS16 crash (game builds code with two stores side-by-side, Rosetta resumes one byte late). With switch on, Wine keeps RWX pages non-writable, lets each store through one at a time.

### Display Safety Switches
- **Retina Mode (RetinaMode registry key):**
  - Default: On (game runs at native resolution).

- **Seed Safe Resolution:**
  - Default: On for first launch.
  - Effect: Writes 1920x1080 (or scaled equivalent) to game's options file if game has never written one.
  - UI toggle: "Start a game that has never run at a safe resolution" (line 16).

- **Binding:** Model provides methods like `metalFXEnabledBinding()`, `sidecarBinding()`, etc., returning Binding<Bool> or Binding<T>.

## 15. Symlink / Unplugged-Volume Handling

### Symlink Handling
Code uses:
- **`standardizedFileURL`** (NFS2015Install.swift:200, 202; NFS2015ClientOutputLog.swift:53) - Resolves . and .. in path; does not resolve symlinks.
- **`.resolvingSymlinksInPath()`** (NFS2015Install.swift:200; NFS2015ClientOutputLog.swift:54) - Follows symlinks to actual path.
- **`isSymbolicLink` resource value** (NFS2015Install.swift:206; NFS2015ClientOutputLog.swift:55-56) - Checks if URL points to a symlink.

### Volume Checks
**Prefix symlink handling (NFS2015Install.swift:200-206):**
```swift
let path = url.standardizedFileURL.resolvingSymlinksInPath().path
let prefix = prefix.standardizedFileURL.resolvingSymlinksInPath()
let values = try prefix.resourceValues(forKeys: [.isDirectoryKey, .isSymbolicLinkKey])
guard values.isDirectory == true, values.isSymbolicLink != true else {
  throw LauncherError.operation("Your Windows folder cannot be a symlink.")
}
```
- Rejects prefix if it is a symlink (not allowed).
- Resolves symlinks in path for comparison.

**Session log symlink validation (NFS2015ClientOutputLog.swift:53-56):**
```swift
let candidate = URL(fileURLWithPath: text).standardizedFileURL
let folder = support.appendingPathComponent("Logs").standardizedFileURL
guard candidate.deletingLastPathComponent().resolvingSymlinksInPath().path == folder.path,
  let values = try? candidate.resourceValues(forKeys: [.isRegularFileKey, .isSymbolicLinkKey]),
  values.isRegularFile == true, values.isSymbolicLink != true
else { return }
```
- Validates session log is in Logs folder and is not a symlink.

### Behavior if Volume Missing
**For prefix symlink (imports player's folder):**
- If player's prefix is a symlink to external volume and volume is unplugged:
  - Path resolution fails.
  - No explicit check in code; would manifest as file-not-found errors when trying to access prefix.
  - lazyError would be "The Windows folder could not be found" or similar (from GuestPath.resolve failures).

**For application support folder:**
- If ~/Library is a symlink or on unplugged volume:
  - NFS2015SessionClient.supportFolder() uses `home.appendingPathComponent("Library/Application Support/NFS2015Mac")` (line 26).
  - standardizedFileURL is called, resolving . and .. but not symlinks.
  - If home itself is symlink (mounted volume), no explicit symlink check on it.

**Reading from code (no explicit unplugged-volume recovery):**
- No volume-present checks in initialization.
- No retry logic for missing volumes.
- Failures propagate as file-not-found errors caught as LauncherError.operation("...").
